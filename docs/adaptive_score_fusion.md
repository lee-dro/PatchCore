# 敏感性引导像素分数融合

## 当前阶段

恢复的是双独立分支的 `image-fixed / pixel-sensitivity + shrinkage(0.25)`。
`legacy` 门控是可选的经验回退规则。历史上它的平均像素结果好于直接收缩和纯敏感性，
因此保留为研究配置，而非宣布它是所有类别的最优方案。
原始单库 PatchCore 与双分支固定分数融合始终保留为两个不同对照。

## 数据流

1. 将 MVTec 的正常训练图按 seed 随机划分。80% 供两个分支分别建记忆库，20% 留作校准。
   测试集不参与建库，校准图不参与建库。划分文件清单存入每次运行的 fusion.json。
2. 相同 WideResNet50 架构的两个实例分别提取 `0.layer2`、`1.layer3`，各自 patchify、采样、最近邻预测。
   两分支共享输入与划分，不共享记忆库。固定 Coreset 比例不等于固定总库大小。
3. 校准集上制造 64 个扰动，类型为小点、细划痕、纹理块，各设三个尺度。
   每张合成图与原正常图配对，用缺陷区域异常响应的增量估计该层敏感性。
   代码中的 `area_0.02/0.04/0.08` 实际是线性长度比例标签，不是精确面积百分比。
   若正常校准图不足64张，会循环选用原图；64是合成样本数，不是64个独立正常来源。
4. 像素响应增量先除以正常图高分位异常响应的稳健离散尺度，再按缺陷组取中位数、跨组取中位数。
   非正响应截为零后归一化；两层均无有效正响应时回退等权。
   因而 `sensitivity-only` 仍有正常尺度标准化，只是不额外乘稳定性奖励。
5. 图像级始终使用 `0.9/0.1`；像素权重取
   `w_pixel = (1 - λ) * [0.5, 0.5] + λ * w_sensitivity`，冻结 λ=0.25。
   注意 λ 越大自适应贡献越大，λ=0 才是固定权重。
6. legacy 门控同时要求：组偏好一致性 ≥0.8，敏感性 layer2 权重 ≤0.8，layer3 相对稳定性 ≥0.9。
   满足时启用收缩，否则像素回退 0.5/0.5。它不查看本次测试 AUROC。
   阈值源于此前探索，因此与当前测试集并不构成完全独立的确认性评价。
7. 两分支测试分数分别做全评估集 min-max，再按权重求和。图像得分不是融合异常图的最大值。
   当前算法在程序中先收集测试输出，再校准，但校准函数不接收测试输出或标签。
   不把执行顺序当作泄漏证明；关键是数据来源与依赖关系。

单库内加权改变的是同一个 embedding 的距离空间，双分支改变的是独立距离分数的组合。
两者不能因都叫 layer2+layer3 就视作同一个模型。

## 运行与开关

在 VS Code 选择仓库唯一的 launch 配置；Python 解释器使用当前 `patchcore` conda 环境。
配置中的 Python 与 MVTec 路径针对当前电脑；换机器时需要修改这两处路径。
配置显式写出训练划分、分支、两个任务的基准权重、λ 及三个 legacy 门限。

| 目的 | 修改当前 launch 参数 |
|---|---|
| 默认四组对比 | 保留所有参数 |
| 不使用门控 | 删除 `--sensitivity_gate`，保留 λ=0.25 |
| 仅双分支固定分数 | 删除 `--task_decoupled_ablation`、`--pixel_sensitivity_shrinkage` 及其值、`--sensitivity_gate` |
| 原始单库对照 | 在固定配置基础上只保留一个 `-b wideresnet50`，层改为 `-le layer2 -le layer3`，删两组任务权重 |

公平配对时保留相同的 `--train_val_split 0.8`，即使固定/原始方法不使用校准图。
全训练集原始基线也可以另跑，但必须单独标注，不能混为同一数据预算。
`--num_workers 0` 用于当前 Windows 补跑，减少工作进程启动开销；不是算法改进。

PowerShell 批量补跑：

```powershell
$env:PYTHONPATH = "$PWD/src"
python bin/benchmark_fusion.py
```

默认 bottle、pill、transistor，seed 0–4，每组分别训练原始单库和双分支。
共 30 个训练命令、75 行方法指标；四种双分支方案复用同一组预测，不重复训练。
类别在本次执行前固定，包含旧的收益和失败案例，并非新 holdout 类别。
`protocol.json` 在运行前记录设置及源码 SHA256，续跑遇到配置或源码变化会拒绝混用。
只复核历史表格用 `--historical-only`；已完成补跑只重算汇总用 `--analyze-only`。

## 输出含义

- `results.csv`：各方法三项 AUROC。`Mean__方法` 只在同方法内取均值，不把消融方法混平均。
  `full_pixel_auroc` 统计整个测试集的像素；`anomaly_pixel_auroc` 只选异常图像，
  但仍统计这些图像的全部像素，不是仅用缺陷掩码内的像素。
- `mvtec_<category>_fusion.json`：各方法权重、校准诊断、门控决策、数据划分与计时。
- `selected_variant`：实际主输出；保存模型与可视化使用它，重载会恢复它。
  旧版自适应 JSON 如保存了 variants，加载器优先恢复对应方法，避免误用顶层基准权重。
- `fit_time_s`：各分支 fit 之和；`calibration_time_s`：合成、校准预测、估权和门控开销。
- `predict_time_s`：测试分支预测之和加主输出融合；`fusion_time_s` 是整套消融融合时间。
- `fit_calibration_predict_time_s`：上述主方法的 fit+校准+predict。校准属于一次性建模成本，非每张图重新运行。
- `evaluation_time_s` 单列指标统计时间；`dataset_wall_time_s_before_save` 还包含初始化等，但不含模型保存。

使用 `--save_patchcore_model` 保存分支模型与 fusion.json。
`--save_segmentation_images` 输出主方法热图；图名包含缺陷子目录，避免不同缺陷的 `000.png` 相互覆盖。

## 已知局限与不做的事

- 归一化仍依赖整个测试样本集合，不用标签但属于离线评估方式；尚不是可直接部署的单图校准。
- 合成图可能落在背景，形态、对比度和分布不一定匹配真实缺陷；跨组合成一致性不等于真实缺陷一致性。
- 门控只改变最终像素权重，不跳过分支建库、校准或测试预测。回退不会节省本次双分支计算成本，
  它也不是“不训练就能判断类别适用性”的分类器。
- legacy 对完全并列的组响应沿用 `argmax` 的首分支规则，以保留历史语义。
  可选 conservative 模式加入 margin 和组级 bootstrap 约束，但本次不启用、不重新调门限。
  组级置信区间不是独立样本置信区间，也不提供统计风险上界。
- 旧 combined、stability、regularized 模式保留为兼容消融入口，不是推荐主线。
  单库 `--layer_fusion_weight` 也只保留用于重现失败对照；默认配置没有它。
- 5 个 seed 反映划分/采样随机性，不等于 5 个新测试数据集。
  统计推断按类别均值配对，不把同类别 seed 当作独立类别。
- 历史 15 类原始命令/划分清单缺失。本次新协议不能宣称逐位复现历史“最佳成绩”。
  原有 `PROJECT_CONTEXT.md` 在先前桌面路径未找到，后续提供时应同步这些阶段与限制。

## 2026-10-22 冻结协议结果

在 bottle、pill、transistor 各 5 个 seed 的补跑中，类别等权的双分支固定基线为参照。
原始单库在图像 AUROC 上高 `0.009161`，但全像素和异常像素分别低 `0.004087`、`0.003855`。
纯敏感性像素融合分别低 `0.014347`、`0.014618`；λ=0.25 收缩分别低 `0.001866`、`0.002080`；
legacy 门控将差距缩小为 `0.000500`、`0.000537`，仍没有超过固定基线。
门控启用 11/15 次：bottle 5/5、pill 4/5、transistor 2/5。

因此本次实验回答的是：门控在这三类上有一定风险缓冲作用，但尚未证明具有泛化收益。
它的意义是给出可解释的适用边界和回退机制，而不是把它作为默认性能改进。
